## A. PostgreSQL integration tests (prioritas pertama)
1. Verifikasi `compose.yaml` dengan PostgreSQL 17 dan `.env` lokal, tanpa mencetak secret. Gunakan database TEST terpisah; jangan gunakan database produksi atau menghapus volume/data yang ada.
2. Review SQL `migrations/000001_phase2.up.sql` dan down migration: foreign key, unique constraints, indeks, idempotency, transaksi, keamanan default, dan reversibility. Perbaiki temuan secara aman memakai migration baru jika sudah ada data; hindari rewrite migrasi yang sudah diterapkan.
3. Jalankan migrasi eksplisit hanya pada database test yang ditentukan operator, lalu `go test -v -tags=integration ./internal/database -count=1`. Bila perlu, tambah integration tests untuk concurrency/idempotency, rollback, isolasi account, insert snapshot dan collector failure.
4. Fail safe: tidak boleh auto-create/drop database, auto-run migration, truncate, atau `docker compose down -v`. Jika `DKO_TEST_DATABASE_URL` tidak ada, skip integration test dengan alasan jelas, bukan klaim PASS.
5. Jalankan `sqlc generate` hanya jika binary tersedia; jika tidak, cek konsistensi query SQL dengan generated code dan laporkan statusnya.

## B. Credential vault end-to-end
1. Tambahkan UI administrasi sederhana berbahasa Indonesia untuk mendaftarkan, memperbarui dan menonaktifkan akun provider serta menyimpan credential terenkripsi ke PostgreSQL. Hanya admin terautentikasi yang boleh mengaksesnya.
2. Gunakan `internal/vault` dan `internal/credentials` yang sudah ada. Jangan membuat mekanisme enkripsi kedua. Master key tetap dari environment dan tidak disimpan di database.
3. Collector ProxyRack, Repocket, dan TraffMonetizer membaca credential akun aktif dari vault melalui service layer (multi-account bila skema mendukung), bukan menjadikan `.env` sebagai satu-satunya sumber. Dukung transisi dari konfigurasi lama secara eksplisit, tanpa otomatis mencatat plaintext ke database.
4. Jangan tampilkan kembali API key/password/token, ciphertext, nonce, atau nilai auth header di UI, response JSON, exception, test logs, maupun audit logs. Gunakan placeholder semisal `Tersimpan`; perubahan credential memakai nilai baru dan tidak pernah mem-prefill secret.
5. CSRF pada seluruh mutasi admin, validasi input, authz owner/admin, rate limit sesuai kebutuhan, audit event tanpa rahasia, dan penanganan error Bahasa Indonesia yang tidak bocorkan rincian internal.
6. Karena provider API nonresmi bisa berubah, pertahankan mode read-only eksternal: jangan add/delete device, payout, atau mutasi akun di provider. Operasi lokal konfigurasi akun diperbolehkan.
7. Hindari SSRF: endpoint provider dari allowlist atau validasi ketat; jangan izinkan arbitrary URL via form. HTTP clients timeout dan tidak otomatis redirect lintas domain.

## C. Tests & review keamanan
- Unit tests untuk vault CRUD flow, auth/CSRF, masking, credential lookup, multi-account isolation, provider disabled, credential invalid, DB failure, dan provider failure tanpa saldo nol palsu.
- Integration tests untuk penyimpanan dan pembacaan encrypted credentials serta snapshot dengan database test.
- Jalankan `gofmt`, `go test ./...`, `go vet ./...`, `go test -race ./...` bila tersedia, `git diff --check`.
- Review cookie HTTPS, query-token yang sudah dihapus, security headers, session invalidation, dan tidak adanya leakage.
- Perbarui `.env.example`, README, docs/SECURITY.md, dan docs/PHASE2-CHECKPOINT.md dengan setup PowerShell yang aman. Jangan commit `.env`, secret, database dump, atau hasil test privat.
- Jangan membuat GitHub Actions. Jangan deploy VPS, menjalankan migration produksi, atau merge `main`.
