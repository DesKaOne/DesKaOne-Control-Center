# Prompt 004 — Fix PostgreSQL Reading Identity & Re-run Integration Tests

Repository: https://github.com/DesKaOne/DesKaOne-Control-Center  
Branch: `feat/phase2-postgresql-security`

## Bukti bug nyata (Windows, PostgreSQL 17.11)
Migration 000001, 000002, 000003 sukses pada database test `deskaone_control_test`. Integration test `TestPostgresRecordIsIdempotentAndRetainsBalanceOnFailure` gagal dengan `saldo gagal dipertahankan: {Provider: Balance: Currency: State: Message: CheckedAt:0001-01-01 ...}`. Test credential isolation dan URL validation PASS.

Audit awal: `LatestReadings()` pada `internal/database/store.go` SELECT `pa.id::text` dan memakai UUID sebagai key map, sedangkan integration test memakai `got[id]` dengan `id` merupakan slug `integration-...`; missing key menghasilkan zero-value struct tanpa error. Namun jangan berhenti di perbaikan test saja: audit seluruh jalur identitas agar perilaku aplikasi benar, termasuk multi-account.

## Instruksi
1. Sebelum coding, pastikan branch benar, working tree bersih; `git fetch` dan `git pull --ff-only` hanya jika aman. Jangan reset/rebase/force-push/merge.
2. Baca `AGENTS.md`, `docs/PHASE2-VALIDATION.md`, `internal/database/store.go`, `internal/database/store_integration_test.go`, `internal/app/app.go`, `internal/collectors/collectors.go`, dan tests terkait.
3. Tentukan kontrak identitas eksplisit: UUID account ID adalah key unik lintas provider accounts; slug provider adalah metadata. Pastikan `Reading.Provider` / `Collector.ID()` dipetakan dengan konsisten untuk akun legacy default dan akun vault multi-account. Hindari menggabungkan atau menimpa saldo dua akun provider sama.
4. Perbaiki key lookup / mapper yang keliru dengan perubahan minimal yang kompatibel dengan dashboard, `RecordReading`, `LatestReadings`, dan interface repository. Tes harus memeriksa keberadaan key secara eksplisit (dua-value lookup) sehingga missing key tidak salah didiagnosis sebagai saldo hilang. Tambahkan regression tests multi-account dan status error terakhir vs saldo sukses terakhir.
5. Jika data benar-benar tidak ada, diagnosa SQL transaction/idempotency secara menyeluruh dan perbaiki akar penyebabnya. Jangan menghapus atau menormalisasi kegagalan test melalui hardcoded expected data.
6. PostgreSQL 17.11 test sudah ada. Jangan mengulang migration 000001–000003 yang sudah diterapkan. Jangan DROP/TRUNCATE database, hapus volume, atau jalankan migrasi produksi. Jalankan integration test memakai `DKO_TEST_DATABASE_URL` yang menunjuk localhost dan nama DB test, tanpa mencetak credential. Jika env tidak ada pada sesi Codex, catat SKIP secara jujur, serta beri perintah operator untuk menjalankan ulang pada PowerShell yang sudah terkoneksi.
7. Jalankan `go test ./...`, `go vet ./...`, `go test -race ./...`, `git diff --check`, serta `go test -v -tags=integration ./internal/database -count=1` saat URL test tersedia. Perbarui `docs/PHASE2-VALIDATION.md` dan `docs/PHASE2-CHECKPOINT.md` dengan hasil aktual PASS/FAIL/SKIP, detail root cause dan bukti.
8. Jangan ubah repo lain, deploy VPS, menambah provider, atau merge ke main. Tidak perlu migrasi baru jika akar masalah hanya mapping identitas. Jangan commit `.env` atau secret.
9. Commit perubahan kode lokal pada branch ini setelah validasi yang tersedia. **Jangan push kode atau buat PR** tanpa instruksi berikutnya.

Akar masalah, file diubah, kontrak key yang dipilih, apakah bug dashboard ikut terdampak, rincian hasil test nyata (terutama test saldo, concurrent idempotency, credential), migration status (tidak dijalankan ulang), SHA commit lokal, status working tree, dan perintah PowerShell singkat untuk rerun. Jangan klaim Phase 2 PASS penuh selama integration test belum seluruhnya hijau.
