## 1. Audit referensi CashPilot
- Referensi hanya untuk riset perilaku API: https://github.com/GeiserX/CashPilot/tree/main/app/collectors
- Audit khusus `honeygain.py`, `earnapp.py`, dan `packetstream.py`, beserta `base.py` dan registrynya. Catat URL/method, payload, skema respons, satuan, metode autentikasi, waktu kedaluwarsa token, dan batasan yang belum dapat dipastikan dalam `docs/PROVIDER-CONTRACTS.md`.
- Implementasi tetap **Go**, bukan runtime Python atau menyalin kode CashPilot secara verbatim. Tinjau lisensi dan syarat akses provider. Jangan mengakali CAPTCHA, anti-bot, MFA, paywall, atau melakukan scraping yang tidak diizinkan. Bila integrasi tidak layak atau tidak terverifikasi, jadikan provider `unsupported` atau `needs-review` dengan alasan, bukan mengarang kontrak.
- Tidak ada penggunaan akun/credential sungguhan atau permintaan ke provider live di unit/integration test.

## 2. Implementasikan 3 adapter awal (sesuai hasil audit)
- Target batch: **Honeygain, EarnApp, PacketStream**. Masing-masing independen, dengan constructor/factory sesuai kontrak collector saat ini. Jangan berasumsi ketiganya sama-sama memakai API resmi atau satu tipe autentikasi.
- Tambah katalog provider/allowlist dan field credential per provider di admin `/admin/providers`, bila UI saat ini menerapkan daftar provider statis; jangan menambahkan arbitrary URL, command execution, atau kemampuan mutasi provider.
- Credential hanya dari vault untuk akun baru; fallback legacy `.env` tetap terbatas ke aturan akun `default` dan tidak diperluas otomatis ke layanan baru. Jangan masukkan token/password/cookie dalam response API, HTML, log, audit, atau pesan error.
- Semua HTTP memakai timeout, context cancellation, response size limit, HTTPS, redirect policy ketat (default blokir redirect, terutama lintas domain), status 401/403 -> `auth`, timeout/network/upstream/malformed terklasifikasi; retry hanya untuk operasi aman dan dengan batas. Gunakan `httptest`/injected endpoint internal pada test; jangan terima URL bebas dari admin.
- Representasikan saldo dengan presisi yang tepat tanpa floating-point untuk nilai uang (gunakan string decimal/konversi integer unit terkecil), serta pastikan currency/unit yang benar berdasarkan kontrak. Poin, bandwidth, pending earnings, withdrawable balance, dan verified earnings adalah metrik terpisah; jangan klaim satu jenis sebagai lainnya.
- Jika collector gagal atau token expired, jangan menulis saldo palsu nol; pertahankan snapshot sukses terakhir dan tampilkan status serta waktu pemeriksaan terkini.
- UUID account ID tetap identitas tunggal penyimpanan; dukung multiple accounts per provider tanpa data collision.

## 3. Test & quality gates
- Tambah unit tests terisolasi untuk tiap provider: sukses, 401/403, 5xx, timeout/network, malformed JSON, missing field, invalid currency/unit, expired credential, redirect blocked, serta multi-account factory. Tidak ada network eksternal.
- Regression tests untuk integrasi vault dan pemetaan UUID account ID -> provider metadata. Uji pemisahan saldo, points/bandwidth dan verified earnings.
- Jalankan `gofmt`, `go test ./...`, `go vet ./...`, `go test -race ./...`, `git diff --check`.
- Jika `DKO_TEST_DATABASE_URL` tersedia dan menunjuk loopback database `*test*` PostgreSQL 17, jalankan `go test -v -tags=integration ./internal/database -count=1`. Jangan ulang migrasi 000001–000003 pada database yang sudah dimigrasi. Jika URL tidak tersedia, SKIP secara jujur.
- Jangan otomatis membuat/menghapus database atau volume; jangan menjalankan migrasi produksi. Jika memerlukan skema baru, buat migrasi versioned, review terlebih dahulu dan jelaskan alasannya.
